# ClientNest progress

## Start of a task

1. Read `PROGRESS.md` (current week and allowed work).
2. If the requested work is outside that week, say so and either refuse or record a decision in `DECISIONS.md` before proceeding.
3. Read `TOOLING.md` if the work involves MCPs, skills, or hooks.

## During work

Stay inside the current week's required output in `PROGRESS.md`. Interview rows may be `skipped` — do not delete them. Build v1 modules unless `PROGRESS.md` says otherwise.

## End of a task

Update `PROGRESS.md`:

- Set the item status to `done`, `in progress`, or leave `not started`.
- Put a real evidence path or count in the Evidence column.
- Set **Last updated** to today.
- Only mark **Current status** fields that actually changed.

If you changed scope, timing, stack, or tooling schedule, add a row to `DECISIONS.md`.
If you enabled or deferred an MCP/skill/hook, update `TOOLING.md`.

## Status vocabulary

Use only: `not started`, `in progress`, `done`, `blocked`. Counts look like `3 / 15`.
